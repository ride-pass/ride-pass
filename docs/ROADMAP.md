### 코드 구조에서 알아 둘 것

- **데이터:** 화면은 `src/data/repository.ts`만 부른다. 요약 숫자는 `derive.ts`에서 계산한다(4절). 알림(`RiderNotice`)은 시연 중 생기는 상태라 `repository.ts`에 있다.
- **신용 정보:** 기사 화면은 `getRiderCreditView()`만 쓴다. 기관에 가는 리포트는 `partnerView.ts`(직원 화면 없음, 테스트로 확인). eslint가 막는다(2-4).
- **창 사이 동기화:** `src/data/demoSync.ts`가 같은 브라우저의 다른 창끼리 BroadcastChannel로 "무엇을 바꿨는지"만 주고받는다(분할 보기는 지웠지만 코드는 남음). 브라우저 저장소는 안 쓴다. 새로고침하면 처음으로.
- **화면 틀:** `src/components/shell/PhoneFrame.tsx`(768px↑ 휴대폰 모양, 인쇄 때 해제).
- **문구:** `src/i18n/ko.json`, `id.json`에만. 인니어는 원어민 검수 전이다.

## 4. 시연 진행 순서 (초안, 리허설에서 고친다)

준비: 노트북 Chrome, 창을 넓게(1440px 정도). 시작 직전에 **새로고침** 한 번(깨끗한 상태).

1. `https://ride-pass.vercel.app/?demo=1` → 조작판 「시연 단계로 바로 가기 1」 → 렌털 신청 화면에서 「Trailcred로 수입 명세서 제출하기」
2. 온보딩 → 로그인: 번호 `812-0000-0101`(Budi) → 인증 문자 「자동 입력」
3. 동의: 무엇을·누구에게·얼마 동안, "거절해도 렌털 신청은 그대로" → 맨 아래 「동의합니다」 체크 → 「동의하고 계속하기」
4. 촬영: 찾는 중 → 찾음 → 촬영 → AI 읽기 → 신뢰도. 선택 자료로 SLIK 샘플
5. 수입 명세서(서류 모양, 인쇄 가능) → 「제출할 곳 고르기」에서 렌털사 D를 눌러 고름(처음엔 아무 곳도 안 골라져 있다) → 「1곳에 제출하기」 → 공유 완료 3단계
6. 내 신용 상태: 신용도 + PKA 배지 → 요인별 상태의 **아무 요인이나 눌러 근거 서류**를 보여 준다(상환 이력 = 렌털 납부·SLIK·통신요금, 검증된 소득 = 입금 내역과 일치율 등, 모두 가상 예시 + 워터마크). 창 맨 아래 「이 요인을 올리려면」 (#55)
7. 하단 탭 「추천」: 내 등급으로 볼 수 있는 가상 상품과 추천 3개(「중개 제휴 후 제공 기능」 배지, 예시 금리) → 조작판 「보낸 곳 결과 보내기 (승인)」 → **"열람했습니다", "승인했습니다" 알림**과 종에 안 읽음 표시
8. KUR 체크리스트(하단 탭 「마이」 → KUR 신청 준비, 금리·한도 없음)

### 멘토에게 확인할 것

CLAUDE.md의 "멘토 확인이 필요한 결정"(기술 스택 변경, 2절 규칙 해석, 시연 시나리오 변경)에 걸리는 것부터 적었다. 멘토링 뒤 결과를 항목마다 적는다.

**CLAUDE.md 규칙 변경**

1. **11/20에 고친 CLAUDE.md 규칙 세 군데를 그대로 둬도 되는지.** ① 4-5절: 렌털사 점수는 기사가 공유한 항목만으로 계산(#24) ② 4-5절: 기사 화면은 가장 큰 이유 한 줄 + 「평가 기준 보기」 창(#26) ③ 8절 체크리스트를 ②에 맞게 수정.
   - 이유: CLAUDE.md는 멘토가 쓴 문서이고 "규칙 변경은 팀 합의 후"인데, 리뷰 없이 합쳤다. 안 된다고 하면 되돌린다.

**규제·규칙 해석 (2절)**

2. **C단계 「제출할 곳 고르기」에 점수를 보여 주는 것(#26).**
   - 이유: "고른 곳에는 이 점수가 그대로 보입니다"는 제3자에게 점수를 넘기는 걸 직접 보여 주는 장면이다(PKA 업무 그 자체). C단계에서만 보이고 「PKA 인가 후 제공 기능」 배지가 붙지만, 발표에서 "인가 후 모습"으로 분명히 읽히는지 확인.
3. **이유 3개를 「평가 기준 보기」 창 안으로 접은 것.**
   - 이유: 원래 규칙은 "설명 없는 점수는 만들지 않는다", "이유 3개와 함께"였다. 지금은 가장 큰 이유 한 줄과 버튼만 바로 보인다. 이 정도면 설명이 충분한지.
4. **평가 기준 창에 반영 비율(25·20·20·15·15·5)을 공개한 것.**
   - 이유: 비율은 검증 전 가설인데 숫자로 공개하면 확정 모델처럼 보일 수 있고, 기사가 점수를 올리려고 자료를 맞출 수 있다. 공개(투명성)와 비공개 중 어느 쪽인지.
5. **활동 기록을 공유하지 않으면 C단계 점수를 "평가 보류"로 하는 것(#24).**
   - 이유: 동의 화면에서 활동 기록은 선택인데, C단계에서는 빼면 점수가 안 나와 사실상 필수가 된다. "거절해도 렌털 신청은 그대로 진행됩니다" 원칙에 어긋나는 불이익인지(점수 대신 사실 리포트만 간다).
6. **A단계 화면의 "4 / 5"(충족 요인 수)가 숫자 신용점수로 오해될 여지가 없는지(2-2).**
   - 이유: A단계에서는 숫자 점수를 보여 주면 안 되는데, 큰 숫자로 쓴 "4 / 5"가 점수처럼 보일 수 있다.

**시연 시나리오 변경 (9절)**

7. **처음 8단계에 없던 장면이 시나리오 변경으로 보이는지:** 분할 보기, 기사 앱 알림, 수입 명세서 인쇄, 제출 화면 "함께 보내는 내용" 카드, 평가 기준 창.

## 6. 작업 방법과 주의할 점

```bash
git switch main && git pull
git switch -c feat/작업-이름
npm install
npm run dev        # http://localhost:3000
npm run lint && npm test && npm run build   # PR 전에 반드시
```

- **PR:** 설명에 "2절 확인함". CI(lint·test·build)가 PR마다 자동으로 돈다. 팀원 1명 승인 후 합친다.
- **충돌 피하기:** `ko.json`/`id.json`은 거의 모든 PR이 고친다. 같은 날 여러 명이 고치면 먼저 합친 사람 뒤에 `git pull` 후 다시 맞춘다.
- **쌓인 PR:** 아래 PR을 합친 뒤 위 PR의 base를 `main`으로 바꾸고 나서 브랜치를 지운다. 먼저 지우면 위 PR이 닫힌다.
- **Vercel 미리보기:** 팀원은 PR 미리보기를 못 연다. 열려면 계정 주인이 Settings → Deployment Protection에서 Vercel Authentication을 끄거나, 특정 주소만 예외로 넣거나, 배포별 Shareable Link를 보낸다(Hobby 플랜 가능, 비밀번호 보호는 불가).
- **확인은 production 빌드로:** `npm run build && npx next start -p 3100`. 개발 서버를 오래 켜 두면 `/`가 404로 나올 때가 있다. 다시 켜면 된다.
- **분할 보기:** 한쪽 iframe만 새로고침하면 그쪽만 처음 상태가 되어 어긋난다. 분할 보기 화면 전체를 새로고침한다. 같은 브라우저에 앱 탭이 여러 개면 그 탭끼리도 상태가 맞춰진다.
- **움직임:** 모든 애니메이션은 `motion-safe:`라서 '동작 줄이기' 설정이면 멈춘다. 화면 전환은 0.24초다.
